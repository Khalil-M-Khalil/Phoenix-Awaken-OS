# خارطة أدوات Phoenix Awaken OS

## المبدأ

لا ينبغي أن يصبح Phoenix Awaken OS نسخة أخرى من توزيعات الاختبار التي تجمع عشرات الأدوات بلا سياق. الأداة المناسبة هنا هي التي تزيد قدرة المستخدم على حفظ الدليل، تفسيره، تقليل المخاطر، أو توثيق القرار، مع عمل محلي واضح وامتلاك المشروع رخصة وصيانة معقولتين.

## التوصيات ذات الأولوية

| الأولوية | الأداة أو الطبقة | القيمة داخل Phoenix | القرار المقترح |
|---|---|---|---|
| P0 | Syft 1.51.0 | إنشاء SBOM للصورة والبرامج والاعتماديات بصيغ JSON وSPDX وCycloneDX | **مضاف إلى صورة البناء** عبر `/usr/local/bin/syft` |
| P0 | Grype 0.117.0 | فحص صورة النظام والمجلدات وSBOM مقابل الثغرات المعروفة | **مضاف إلى صورة البناء**؛ تحديث قاعدة البيانات يتم صراحةً عبر `phoenix-security-update-db` |
| P0 | Gitleaks 8.30.1 | كشف الأسرار في الكود والملفات والمستودعات قبل النشر | **مضاف إلى صورة البناء** مع `--redact` وتقارير JSON |
| P1 | The Sleuth Kit | تحليل أنظمة الملفات والأقراص من خلال أدوات CLI مناسبة للتحقيقات | إدراجه اختيارياً وبصلاحيات قراءة فقط، مع تحذير واضح قبل فتح صورة قرص |
| P1 | Zeek | إنتاج سجلات تحليلية من حركة الشبكة المصرح بها، وليس مجرد قائمة اتصالات | حزمة اختيارية للمختبر أو محلل الشبكة، مع تعطيل الالتقاط الافتراضي |
| P1 | YARA 4.5.8 | مطابقة قواعد محلية على الملفات المشبوهة وربط النتيجة ببصمة الدليل | **مضاف إلى صورة البناء**؛ القواعد يحددها المستخدم أو حزمة Phoenix موثقة لاحقاً |
| P1 | Volatility 3 | تحليل ذاكرة RAM المأخوذة بإذن المستخدم | حزمة اختيارية للخبراء؛ ليست جزءاً من تجربة المستخدم الأساسية |
| P2 | أدوات Linux الأصلية | journalctl، ss، lsof، nftables، cryptsetup، smartctl، osquery-like inventory | تقديم واجهة Phoenix تشرح النتائج بدلاً من إغراق المستخدم بالأوامر |
| P2 | GRC Control Mapper | ربط دليل أو نتيجة بفئة NIST CSF أو ISO 27001 أو COBIT | تطوير طبقة Phoenix أصلية لأنها تمنح النظام تميزاً مهنياً حقيقياً |

## لماذا هذه الأدوات؟

توضح Anchore أن Syft يولد قائمة SBOM من صور الحاويات وأنظمة الملفات، بينما يفحص Grype الصور وأنظمة الملفات وملفات SBOM بحثاً عن الثغرات المعروفة، مع دعم صيغ SBOM الشائعة.[1] هذا يخدم Phoenix Awaken OS مباشرة لأن النظام نفسه صورة bootc يجب أن نعرف مكوناتها قبل نشرها، ويمكن حفظ الـ SBOM ونتيجة الفحص كجزء من حزمة إصدار قابلة للتدقيق.

Gitleaks مناسب لحماية المستودعات والملفات المحلية من تسريب كلمات المرور والمفاتيح والرموز. وثائق المشروع تعرض أوضاع فحص git والمجلدات وstdin، وتدعم تقارير JSON وSARIF وخيار redaction.[2] لكنه حالياً في وضع صيانة أمنية أكثر من كونه منصة ميزات جديدة، لذلك يجب تثبيت نسخة معروفة أو تقييم Betterleaks قبل اعتماد قرار طويل الأمد.

The Sleuth Kit يقدم مكتبة C وأدوات سطر أوامر لتحليل أنظمة ملفات مثل NTFS وFAT وEXT2FS وFFS، ولذلك يناسب وضعاً جنائياً اختيارياً وليس التشغيل الافتراضي.[3] أما Zeek فهو إطار تحليل ومراقبة للشبكة يولد سجلات قابلة للتفسير وله توثيق للإعداد والتشغيل والسجلات والبرمجة.[4] إدراجه يجب أن يكون صريحاً ومحدوداً بالشبكات التي يملكها المستخدم أو يملك تفويضاً كتابياً لمراقبتها.

## الأدوات التي لا أوصي بإضافتها إلى الصورة الأساسية

لا أوصي بإضافة Metasploit أو أدوات سرقة الاعتمادات أو أطر الاستغلال أو أدوات التخفي أو أدوات كسر كلمات المرور إلى تجربة Phoenix الافتراضية. يمكن أن توجد بيئة مختبر منفصلة للمستخدمين المصرح لهم، لكن هذه الأدوات لا تخدم هوية النظام evidence-first، وتزيد سطح الهجوم والالتباس القانوني وتشوّش على المستخدم العادي.

ولا أوصي بإضافة Open SEO إلى النظام الأساسي. هو مشروع مختلف وظيفياً، يعتمد على مصادر بيانات وشبكة واتصالات خارجية، ولا يعزز مسار الأدلة أو النقل المحلي أو GRC بصورة مباشرة. يمكن إنشاء مشروع منفصل له لاحقاً أو موقع مستقل، لكن دمجه في OS سيخفف وضوح المنتج.

## الحزمة الأولى المنفذة

أضيفت Syft وGrype وGitleaks وYARA إلى مسار صورة النظام، كما أضيف المشغّل `phoenix-security-check` لتشغيل الفحوصات محلياً وإنتاج تقارير JSON وملف `run.json` يحتوي على بصمات التقارير. يمكن تحويل التقارير إلى Evidence Capsule باستخدام أمر `phoenix-capsule` الموجود مسبقاً.

لا يتم تحديث قاعدة Grype تلقائياً أثناء الفحص، لأن ذلك قد يفاجئ المستخدم باتصال شبكي. عند توفر شبكة واتصال مصرح، يستخدم المشغّل `phoenix-security-update-db` لتحديث القاعدة كعملية منفصلة. بدون قاعدة محلية، يبقى Grype غير قادر على إصدار حكم ثغرات، ويجب عرض ذلك كحالة غير مكتملة لا كـ "لا توجد ثغرات".

بعد التحقق من هذه الحزمة، نضيف The Sleuth Kit وZeek كحزم اختيارية، ثم نبني Control Mapper الخاص بـ Phoenix لربط كل نتيجة بدليل وقرار وضابط GRC.

## ملاحظة عن الاختبار

تم تثبيت الأصول الرسمية في Containerfile بإصدارات محددة وبصمات SHA-256. اختبر المشغّل على fixture اصطناعي: نجح Syft في إنشاء SBOM، ونجح Gitleaks في إنتاج تقرير دون كشف قيمة السر التجريبية، بينما أظهر Grype بوضوح أن قاعدة الثغرات غير موجودة بدلاً من إعطاء نتيجة مضللة. ما يزال فحص Strix الكامل وإعادة بناء ISO داخل Fedora VM خطوة لاحقة قبل إعلان الحزمة release-ready.

كل أداة جديدة يجب أن تمر عبر فحص ترخيص واعتماديات، اختبار offline، صلاحيات least privilege، اختبارات مسارات الملفات، اختبارات تسرب الأسرار، وفحص Strix على مكونات Phoenix المملوكة. نجاح التثبيت وحده لا يعني أن الأداة صالحة للإصدار.
